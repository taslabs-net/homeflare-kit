# @homeflare/distilled-grafana

This package is **not a HomeFlare SDK**. It is an unmodified copy of
`@distilled.cloud/grafana`, generated by the [distilled](https://github.com/alchemy-run/distilled)
pipeline from Grafana's own committed OpenAPI 3.0.3 document
(`public/openapi3.json` at `grafana/grafana@main`, mirror commit `38c18a03`,
dated 2026-09-11 — see the distilled clone's `packages/grafana/README.md` for
the full provenance and the `v13.1.4`-tag spot-check), published here under
its own name only because `@distilled.cloud/grafana` does not exist on npm
yet — the kit builds it in a local clone of `alchemy-run/distilled` but, per
house policy, never pushes to that upstream. See
[`../alchemy/docs/distilled-interim.md`](../alchemy/docs/distilled-interim.md)
for the full route every distilled-sourced vendor package follows, and why
this one exists at all.

⛔ **Do not hand-edit anything under `src/`.** The whole point of the route
above is that this directory is _copied_, not written — a fix belongs in the
distilled clone's `packages/grafana/`, regenerated, then copied back here.

## What's in it

One service module (`grafana`), 282 Effect-typed operations covering
Grafana's classic HTTP API — datasources, folders, dashboards, alerting
provisioning (alert rules, rule groups, contact points, notification
policies, mute timings, templates), orgs/users/teams/reports/snapshots/
public dashboards — with `catchTag`-able errors for every status the
operations declare, including `PreconditionFailed` (412, a dashboard
`version` conflict on update) and the alerting provisioning writes'
`X-Disable-Provenance` header input.

32 of those 282 (folders, dashboards, alerting provisioning writes) were
added by this package's introducing PR: Grafana's spec marks the whole
classic write surface `deprecated: true`, pointing at a newer
Kubernetes-apiserver route this spec does not describe at all — see the
distilled clone's `packages/grafana/scripts/convert.ts` header and
`patches/*.patch.json` for the fix, and
[`../alchemy/docs/grafana.md`](../alchemy/docs/grafana.md) for how this
was measured.

```ts
import * as Grafana from '@distilled.cloud/grafana'; // aliased onto this package — see docs/distilled-interim.md
import * as Effect from 'effect/Effect';

const program = Grafana.Services.grafana
  .getFolderByUID({ folder_uid: 'my-folder' })
  .pipe(
    Effect.provide(
      Grafana.fromApiKey({ apiKey: '...', apiBaseUrl: 'https://grafana.example.com' }),
    ),
  );
```

Kit code never imports `@homeflare/distilled-grafana` directly — always
`@distilled.cloud/grafana`, aliased in the consuming package's `package.json`
(`"@distilled.cloud/grafana": "npm:@homeflare/distilled-grafana@<version>"`),
so the eventual cutover to the real published package is a one-line alias
swap with no import changes anywhere in the kit.

## Updating it

From the distilled clone's `homeflare/grafana` worktree:

```sh
pnpm --filter @distilled.cloud/grafana run generate
pnpm --filter @distilled.cloud/grafana run typecheck
pnpm format && pnpm specs:check
```

Then copy `src/` here verbatim, add a changeset (patch — the generated
content changed but nothing new is callable; minor — a new capability like
the folder/dashboard/alerting-provisioning operations this PR adds becomes
callable, per the kit's own new-feature-vs-swap convention), and let the
kit's normal release flow publish it and bump this package's own `version`.
