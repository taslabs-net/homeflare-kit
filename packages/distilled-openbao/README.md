# @homeflare/distilled-openbao

This package is **not a HomeFlare SDK**. It is an unmodified copy of
`@distilled.cloud/openbao`, generated by the [distilled](https://github.com/alchemy-run/distilled)
pipeline from OpenBao's own generated OpenAPI document — `GET /v1/sys/
internal/specs/openapi`, read off a throwaway local `bao server -dev`
(OpenBao 2.6.2) with the stock backends the kit family manages mounted, the
same way `openbao/openbao`'s own `scripts/gen_openapi.sh` builds one. No
production OpenBao was read to build this package. Published here under its
own name only because `@distilled.cloud/openbao` does not exist on npm yet —
the kit builds it in a local clone of `alchemy-run/distilled` but, per house
policy, never pushes to that upstream. See
[`../alchemy/docs/distilled-interim.md`](../alchemy/docs/distilled-interim.md)
for the full route every distilled-sourced vendor package follows, and why
this one exists at all.

⛔ **Do not hand-edit anything under `src/`.** The whole point of the route
above is that this directory is _copied_, not written — a fix belongs in the
distilled clone's `packages/openbao/`, regenerated, then copied back here.

⚠️ **License.** Apache-2.0, not the kit's usual MIT — this content is a
redistribution of `alchemy-run/distilled`'s own Apache-2.0-licensed output,
and relicensing a copy would misstate what it is. See `LICENSE`.

## What's in it

53 service modules, one per OpenBao mount/backend bucket (bucketed from each
operation's own `operationId` — `policies`, `kv`, `pki`, `approle`, `ssh`,
`database`, `jwt`, `kubernetes`, `oidc`, `userpass`, and every `sys/*`
sub-area), with `catchTag`-able errors. Only one resource-specific tag exists
so far — `PolicyNotFound` on `policiesReadAclPolicy` — declared from what was
actually measured against the ephemeral dev server (see
`patches/policies/_errors.json` in the distilled clone); more are added as
each kit family migrates onto this SDK.

The copied source is distilled commit
`52a18936d4e46786c005424549b6085c144ce047` (2026-09-24). Its auth-method and
secrets-engine inventories return typed maps keyed by exact mount path. The
OpenBao 2.6.2 OpenAPI document omits both response schemas; source-side Smithy
patches derive them from the pinned server's `vault/logical_system.go`
`mountInfo`, `handleAuthTable` and `handleMountTable`, cross-checked against the
official Go API client. See `packages/openbao/patches/mount-tables.md` in that
source commit for provenance and reproduction.

Only those two inventory operations require and validate a `data` map.
Unknown metadata and nested mount paths survive; malformed bodies fail with
`OpenBaoParseError` without response values. An explicit empty map is valid.
HTTP failures remain typed errors, including a 404 of the table endpoint;
individual mount absence is a missing key in a successful inventory. This
does not add auth/login envelope support or custom plugin endpoints.

```ts
import * as OpenBao from '@distilled.cloud/openbao'; // aliased onto this package — see docs/distilled-interim.md
import * as Effect from 'effect/Effect';

const program = OpenBao.Services.policies
  .policiesReadAclPolicy({ name: 'agent' })
  .pipe(
    Effect.provide(OpenBao.OpenBaoProtocol),
    Effect.provide(
      OpenBao.credentials({ token: '...', addr: 'http://127.0.0.1:8200', namespace: 'homeflare' }),
    ),
  );
```

House plugins (`openbao-plugin-secrets-cloudflare`, the Proxmox secrets
plugin) are **not** stock `bao` and are not covered here — their specs are a
separate, tracked follow-up.

Kit code never imports `@homeflare/distilled-openbao` directly — always
`@distilled.cloud/openbao`, aliased in the consuming package's `package.json`
(`"@distilled.cloud/openbao": "npm:@homeflare/distilled-openbao@<version>"`),
so the eventual cutover to the real published package is a one-line alias
swap with no import changes anywhere in the kit.

## Updating it

From an isolated worktree of the recorded distilled source commit:

```sh
DISTILLED_SPECS_LOCAL=1 pnpm generate openbao   # or pnpm specs:sync first for a real refresh
pnpm typecheck:ci && pnpm specs:check && pnpm format:check
```

Then copy `src/` back here (`cp -R`, `diff -rq` to prove it), update the source
commit above, and add a changeset. Changesets owns the package version bump.
