# @homeflare/distilled-openbao

## 0.2.0

### Minor Changes

- [#263](https://github.com/taslabs-net/homeflare-kit/pull/263) [`502777b`](https://github.com/taslabs-net/homeflare-kit/commit/502777bba73e13bfc4a3068308feffe0c6052142) Thanks [@taslabs-net](https://github.com/taslabs-net)! - Add `@homeflare/distilled-openbao`, an unmodified copy of the (not yet
  upstream-published) `@distilled.cloud/openbao` SDK — 53 service modules
  across every mount/backend bucket OpenBao's own generated OpenAPI document
  describes (`policies`, `kv`, `pki`, `approle`, `ssh`, `database`, `jwt`,
  `kubernetes`, `oidc`, `userpass`, and every `sys/*` sub-area), with the first
  typed, `catchTag`-able error (`PolicyNotFound`, measured against an
  ephemeral local `bao -dev` server — never against production).

  The spec itself needed no production access either: generated by mounting
  OpenBao's stock backends on a throwaway, loopback-only, in-memory `bao
server -dev` and reading `GET /v1/sys/internal/specs/openapi` — the same
  approach `openbao/openbao`'s own `scripts/gen_openapi.sh` uses. House-only
  plugins (the Cloudflare secrets engine, the Proxmox secrets plugin) are not
  covered — they need their own binaries, a tracked follow-up.

  This follows the kit's established interim-package route (see
  `packages/alchemy/docs/distilled-interim.md`, first established by
  `@homeflare/distilled-netbox`). This PR does not alias
  `@distilled.cloud/openbao` onto it and does not move any of the kit's
  existing hand-written `packages/alchemy/src/openbao/*` resources — the alias
  can only resolve once this package is actually on npm; that migration is a
  follow-up PR.
