# @homeflare/distilled-opnsense

This package is **not a HomeFlare SDK**. It is an unmodified copy of
`@distilled.cloud/opnsense`, generated by the
[distilled](https://github.com/alchemy-run/distilled) pipeline from
OPNsense's own MVC model XML and API controller PHP — OPNsense publishes no
OpenAPI/Smithy/GraphQL description of its API at all, so this converter
reads `opnsense/core`'s `mvc/app/models/OPNsense/<Module>/<Model>.xml` and
`.../controllers/OPNsense/<Module>/Api/*Controller.php` directly, not the
shared OpenAPI dialect every other distilled package uses. Published here
under its own name only because `@distilled.cloud/opnsense` does not exist
on npm yet — the kit builds it in a local clone of `alchemy-run/distilled`
but, per house policy, never pushes to that upstream. See
[`../alchemy/docs/distilled-interim.md`](../alchemy/docs/distilled-interim.md)
for the full route every distilled-sourced vendor package follows, and why
this one exists at all.

⛔ **Do not hand-edit anything under `src/`.** The whole point of the route
above is that this directory is _copied_, not written — a fix belongs in
the distilled clone's `packages/opnsense/`, regenerated, then copied back
here.

⚠️ **License.** Apache-2.0, not the kit's usual MIT — this content is a
redistribution of `alchemy-run/distilled`'s own Apache-2.0-licensed output,
and relicensing a copy would misstate what it is. See `LICENSE`.

## Provenance and version pin

Generated against `opnsense/core` and `opnsense/plugins` tag `26.7.2`. The
edge firewall's exact installed version has **never been measured live**
(SSH to the edge is forbidden by house policy; CrowdSec bans the caller's
IP on a failed probe) — `26.7.2` is inferred, read-only, from a captured
package list (`os-frr-1.54` matches that one tag's plugin tree exactly) and
a runbook stating the box runs "26.7.x". See the distilled clone's
`packages/opnsense/README.md` for the full evidence chain. Patch releases
inside one OPNsense series essentially never change model/controller shape,
so this pin's model XML/controller PHP is very likely correct even if the
edge sits on a different `26.7.x` patch — but it is an inference, not a
measurement, and should be confirmed on the box before this package is
trusted for anything consequential.

## What's in it

8 API controllers, 83 operations — Firewall Alias/Category/Group/Filter
(rules), Routing (Gateways), and the `os-frr` plugin's Quagga/BGP — not
OPNsense's full ~80 configured modules; see the distilled clone's
`packages/opnsense/README.md` for the scope table and what was mechanically
excluded per controller (decorated `get<Item>Action`s, bespoke lifecycle
actions). `catchTag`-able errors cover OPNsense's three-shape
200-with-failure vendor pattern (`{result:"failed"}` validation errors,
`UserWarningException`/`UserInformationalException` at 200) plus the
genuine non-2xx shapes (`UserException`, `DispatchException` 404, the
401/403/400 auth gate) — see `src/protocol.ts` and `src/errors.ts` for the
full mapping with citations back to OPNsense's own PHP source.

```ts
import * as Opnsense from '@distilled.cloud/opnsense'; // aliased onto this package — see docs/distilled-interim.md
import * as Effect from 'effect/Effect';

const program = Opnsense.Services.quagga_general.get({}).pipe(
  Effect.provide(
    Opnsense.credentials({
      apiKey: 'key',
      apiSecret: 'secret',
      baseUrl: 'https://edge.example.com',
    }),
  ),
);
```

Kit code never imports `@homeflare/distilled-opnsense` directly — always
`@distilled.cloud/opnsense` (the alias in `docs/distilled-interim.md`'s
step 5), once that alias exists. This PR does not add that alias and does
not declare any Alchemy `Resource`s on top — see "Not done here" below.

## Not done here

- **No alias, no Alchemy `Resource`s.** The alias can only resolve once
  this package is actually published to npm; adding Firewall
  Alias/Category/Group/Rule (and later Gateways/BGP) resources on top is a
  follow-up PR, gated in part on two open intent questions in
  `docs/alchemy-ledger-network.md` in the landscape repo.
- **No live calls of any kind.** This package has never been pointed at a
  real OPNsense instance; `src/protocol.ts`'s decode logic is grounded in
  vendor source and docs, not runtime-verified. `docs/design.md` in the
  distilled clone's `packages/opnsense/` flags a behavioral trap worth
  reading before building a `Resource` around `setAlias`/`setCategory`/
  `setGroup`: renaming an item through those endpoints triggers a
  server-side cascade that rewrites the old name everywhere it's
  referenced elsewhere in `config.xml`, not just inside the renamed row.
