## 0.1.0

### Minor Changes

- [#326](https://github.com/taslabs-net/homeflare-kit/pull/326) [`c434b4d`](https://github.com/taslabs-net/homeflare-kit/commit/c434b4d6dddfdc952d00d7b391596ad7e7d7d9f7) Thanks [@taslabs-net](https://github.com/taslabs-net)! - Add `@homeflare/seat-runtime`, the model and telemetry layers every coding seat shares. `SeatModel.layer` and `SeatModel.embeddingLayer` give an Effect AI `LanguageModel` and `EmbeddingModel` over LiteLLM on the chat-completions wire (`@effect/ai-openai-compat`, exact rc.115 beside an exact rc.115 `effect` peer). Every request carries the `x-litellm-tags` header, `num_retries: 0`, the response-cache controls (`cache: {no-cache, no-store}`, on by default) and optional `metadata`; the embedding layer reports its dimensions without sending them. `SeatObs.layer` is `OtlpTracer`, `OtlpLogger` and `OtlpMetrics` `.layerFromConfig()` over `fetch` with protobuf, defaulting to CT100's VictoriaTraces, VictoriaLogs and VictoriaMetrics endpoints, and the `OTEL_*` environment still wins (a base endpoint replaces all three defaults, and a `service.name` in `OTEL_RESOURCE_ATTRIBUTES` replaces the default service name). The README states the measured pairing, including the `@effect/platform-node-shared` trap that only a consumer's root `overrides` fixes.

- [#328](https://github.com/taslabs-net/homeflare-kit/pull/328) [`bdc8c4b`](https://github.com/taslabs-net/homeflare-kit/commit/bdc8c4b5c39b3630850c87a40e886bc319ac4e3c) Thanks [@taslabs-net](https://github.com/taslabs-net)! - Add `runRounds` and `mcpToolkit` to `@homeflare/seat-runtime`. `runRounds({ chat, toolkit, maxRounds, onRound })` is the one round loop the seats share: model turn, tool results, model turn, until the model asks for no tools or `maxRounds` tool rounds have run, and then ONE more turn with no toolkit and `toolChoice: 'none'` so a run ends in an answer (`capped` says the cap fired). A provider that still asks for a tool on that forced turn (`AiError` reason `ToolNotFoundError`, which is what `SeatModel`'s compat provider raises, or `InvalidOutputError` from the SDK's own decode) does not fail the run: the result is `capped` and `unanswered`, its `response` is the last tool round's, and `seat_rounds_unanswered_total` counts it (any other failure of the forced turn still fails the run). `maxRounds` must be a positive integer or the run dies with a `RangeError` before any model call. Every turn is a `seat.round` span, counted in `seat_rounds_total` and `seat_rounds_capped_total`. `mcpToolkit(url, headers)` connects the official `@modelcontextprotocol/sdk` client (exact `1.31.0`, a new pinned dependency) over Streamable HTTP and returns the server's tools as a ready-to-run Effect AI toolkit (each a `Tool.dynamic` carrying the server's own JSON Schema) plus `listResources` and `readResource`. A tool failure (`isError`, a JSON-RPC error, a dropped call) is returned to the model as the tool's result, with any echoed query value or header value redacted from its text (a successful result is delivered verbatim); connecting and listing fail with `McpToolkitError`, whose message and `cause` never hold the headers or the query string, nor a query value or header value (6 characters and up) that the server echoes back on its own (a value the server transforms is not caught). The cause is a scrubbed copy of what the SDK threw: name, message, stack and `code`, so `cause instanceof McpError` does not hold; a refused fetch's own `path` field is the full URL under Bun. Results are text: image, audio and blob blocks become one-line markers. `@effect/ai-openai-compat` rc.115 cannot decode a tool call for a `Tool.dynamic` alone (fixed in rc.118), so an argument the server's schema does not declare is dropped until the pin moves. An explicit `null` on an optional argument is delivered to the server as `null`, not deleted. `mcpToolkit`'s `connectTimeoutMs` option (default 15 000 ms; a finite number above 0 and at most 2 ** 31 - 1, or a `RangeError` defect) bounds the WHOLE handshake, `initialize` and the `notifications/initialized` that follows it (the SDK bounds only the first), and each `tools/list` page read at startup, per request and not as a total; `listResources`, `readResource` and tool calls keep the SDK's 60 s. The handshake is interruptible, so a caller's `Effect.timeout` or a shutdown ends it too, and a failed or interrupted `mcpToolkit` leaves nothing in the caller's scope, whether it fails in the handshake or in the `tools/list` after it (the client's finalizer is registered only once the whole toolkit is built), so `Effect.retry` around `mcpToolkit` does not accumulate clients or sockets.

- [#329](https://github.com/taslabs-net/homeflare-kit/pull/329) [`6cffade`](https://github.com/taslabs-net/homeflare-kit/commit/6cffade621fb2c900763b7b7c63b28901cac513e) Thanks [@taslabs-net](https://github.com/taslabs-net)! - Add `@homeflare/seat-runtime/state`: `SeatState`, a seat's Postgres and Valkey as Effect's own services, on a subpath so the root entry stays runtime-neutral. `SeatState.postgres` is `@effect/sql-pg`'s `PgClient` layer (`SqlClient` and `PgClient`), `SeatState.valkey` is `effect/unstable/persistence/Redis` over `Bun.RedisClient` (`Redis`, with `send` and `eval`; `subscribe` fails as `RedisError`), and each has a `*FromEnv` form reading its URL from an environment variable as a `Redacted` secret (`SEAT_POSTGRES_URL`, `SEAT_VALKEY_URL`, or `{ variable }`); `layer` and `layerFromEnv` build both. This package holds no host: every URL is the consumer's. Building a layer connects and authenticates, so a wrong URL, user or password fails at startup as `SqlError`, `RedisError` or `ConfigError`, within `connectTimeout` (Postgres) or `connectionTimeout` (Valkey), 5 s by default. An out-of-prefix write by an ACL'd Valkey user is a typed `RedisError`, and `SeatState.isPermissionDenied` names the server's `NOPERM` (a key outside the user's prefix, or a command outside its categories). Every state call is a span in the run's trace: `@effect/sql-pg`'s `sql.execute` carries `db.system.name=postgresql`, and each Valkey command is a `valkey <COMMAND>` client span with `db.system.name=redis` and the address. A span's attributes never hold a key, value or the URL's password. A FAILED span also exports its error, so a Valkey error is scrubbed of the arguments the server quotes (`unknown command 'X', with args beginning with: '<key>' '<value>'` reaches a caller and the trace as `... with args beginning with: [arguments omitted]`), while a Postgres error's text is not (`@effect/sql-pg` has no hook): a server error that quotes a parameter, such as `invalid input syntax for type integer`, reaches the exported trace. Measured traps, handled: `@effect/sql-pg` leaks a DSN that will not parse (password included) in its error's `cause` and labels spans `localhost:5432` when given only a `url`, so `postgres` parses the URL first and passes host, port, database and user as discrete fields; a `Bun.RedisClient` on its defaults queues commands forever against a dead server and its `connectionTimeout` does not bound DNS, so the layer turns the offline queue off, bounds `connect()` and gives every command a deadline (`commandTimeout`, 10 s). Bun's client also gives up reconnecting after about 31 s of outage (default `maxRetries` 20) and stays dead until `connect()` is called again, so the Valkey layer reconnects itself once Bun gives up (250 ms doubling to 5 s between attempts, one `valkey reconnect` span each, until the layer's scope closes); commands fail at once meanwhile, and `maxRetries` is an option. `@effect/sql-pg` 4.0.0-rc.115 is a new exact dependency, catalogued beside effect. Valkey needs Bun (`Bun.RedisClient`); the Postgres half runs under Node too.
