# @homeflare/distilled-caddy

This package is **not a HomeFlare SDK**. It is an unmodified copy of
`@distilled.cloud/caddy`, built in a local clone of
[distilled](https://github.com/alchemy-run/distilled), published here under
its own name only because `@distilled.cloud/caddy` does not exist on npm
yet — per house policy, the kit never pushes to that upstream. See
[`../alchemy/docs/distilled-interim.md`](../alchemy/docs/distilled-interim.md)
for the full route every distilled-sourced vendor package follows, and why
this one exists at all.

⛔ **Do not hand-edit anything under `src/`.** The whole point of the route
above is that this directory is _copied_, not written — a fix belongs in the
distilled clone's `packages/caddy/`, regenerated, then copied back here.

⚠️ **License.** Apache-2.0, not the kit's usual MIT — this content is a
redistribution of `alchemy-run/distilled`'s own Apache-2.0-licensed output,
and relicensing a copy would misstate what it is. See `LICENSE`.

## What's in it, and what's different about it

One service module, `admin` — Caddy's admin API is a single namespace, not
a multi-tag REST API — covering the 13 operations `/load`, `/adapt`,
`/stop`, `/config/[path]` (GET/POST/PUT/PATCH/DELETE), `/id/<id>[path]`
(GET/POST), `/pki/ca/<id>[/certificates]`, `GET /reverse_proxy/upstreams`.

Unlike every other `@distilled.cloud/*` package, **there is no upstream
spec this was converted from** — Caddy publishes none for its admin API.
Every shape is hand-transcribed from `caddyserver/caddy` v2.11.4 Go source
and caddyserver.com/docs/api, with a provenance comment per shape (see the
distilled clone's `packages/caddy/docs/provenance.md`). `scripts/convert.ts`
there still runs the same `finalizeConvert` reference check every real
converter does, so this package is generated by the same smithy→SDK
compiler as everything else — only the INPUT to `convert.ts` differs.

It ALSO carries typed shapes for Caddy's config TREE (`Services.admin.Config`,
`.AdminConfig`, `.Logging`, `.App`, `.TLS`, …) — generated (not hand-typed)
from Caddy's separate, unversioned config-structure API and restricted to
the modules the house Caddy binary (2.11.4) actually has. See the distilled
clone's `packages/caddy/docs/config-tree.md`. These are for building or
validating a config document; the admin operations' own request/response
bodies (`LoadRequest.config`, `GetConfigResponse.value`, …) still carry
`unknown` — correctly, since a path-based operation can point at any node
of the tree.

```ts
import * as Caddy from '@distilled.cloud/caddy'; // aliased onto this package — see docs/distilled-interim.md
import * as Effect from 'effect/Effect';

const program = Caddy.Services.admin.getConfig({ path: 'apps/http' }).pipe(
  Effect.provide(Caddy.CaddyProtocol),
  Effect.provide(Caddy.fromApiBaseUrl({})), // defaults to http://127.0.0.1:2019
);
```

Kit code never imports `@homeflare/distilled-caddy` directly — always
`@distilled.cloud/caddy`, aliased in the consuming package's `package.json`
(`"@distilled.cloud/caddy": "npm:@homeflare/distilled-caddy@<version>"`), so
the eventual cutover to the real published package is a one-line alias swap
with no import changes anywhere in the kit.

## Updating it

From the distilled clone's `homeflare/caddy` worktree:

```sh
bun scripts/convert.ts && bun scripts/generate.ts
pnpm --filter @distilled.cloud/caddy run typecheck
pnpm format && pnpm specs:check
```

Then copy `src/` here verbatim, bump this package's own `version` (a patch
release — the generated content changed, not this package's own shape), add
a changeset, and let the kit's normal release flow publish it.
