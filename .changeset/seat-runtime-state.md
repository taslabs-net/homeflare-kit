'@homeflare/seat-runtime': minor

Add `@homeflare/seat-runtime/state`: `SeatState`, a seat's Postgres and Valkey as Effect's own services, on a subpath so the root entry stays runtime-neutral. `SeatState.postgres` is `@effect/sql-pg`'s `PgClient` layer (`SqlClient` and `PgClient`), `SeatState.valkey` is `effect/unstable/persistence/Redis` over `Bun.RedisClient` (`Redis`, with `send` and `eval`; `subscribe` fails as `RedisError`), and each has a `*FromEnv` form reading its URL from an environment variable as a `Redacted` secret (`SEAT_POSTGRES_URL`, `SEAT_VALKEY_URL`, or `{ variable }`); `layer` and `layerFromEnv` build both. This package holds no host: every URL is the consumer's. Building a layer connects and authenticates, so a wrong URL, user or password fails at startup as `SqlError`, `RedisError` or `ConfigError`, within `connectTimeout` (Postgres) or `connectionTimeout` (Valkey), 5 s by default. An out-of-prefix write by an ACL'd Valkey user is a typed `RedisError`, and `SeatState.isPermissionDenied` names the server's `NOPERM` (a key outside the user's prefix, or a command outside its categories). Every state call is a span in the run's trace: `@effect/sql-pg`'s `sql.execute` carries `db.system.name=postgresql`, and each Valkey command is a `valkey <COMMAND>` client span with `db.system.name=redis` and the address. A span's attributes never hold a key, value or the URL's password. A FAILED span also exports its error, so a Valkey error is scrubbed of the arguments the server quotes (`unknown command 'X', with args beginning with: '<key>' '<value>'` reaches a caller and the trace as `... with args beginning with: [arguments omitted]`), while a Postgres error's text is not (`@effect/sql-pg` has no hook): a server error that quotes a parameter, such as `invalid input syntax for type integer`, reaches the exported trace. Measured traps, handled: `@effect/sql-pg` leaks a DSN that will not parse (password included) in its error's `cause` and labels spans `localhost:5432` when given only a `url`, so `postgres` parses the URL first and passes host, port, database and user as discrete fields; a `Bun.RedisClient` on its defaults queues commands forever against a dead server and its `connectionTimeout` does not bound DNS, so the layer turns the offline queue off, bounds `connect()` and gives every command a deadline (`commandTimeout`, 10 s). Bun's client also gives up reconnecting after about 31 s of outage (default `maxRetries` 20) and stays dead until `connect()` is called again, so the Valkey layer reconnects itself once Bun gives up (250 ms doubling to 5 s between attempts, one `valkey reconnect` span each, until the layer's scope closes); commands fail at once meanwhile, and `maxRetries` is an option. `@effect/sql-pg` 4.0.0-rc.115 is a new exact dependency, catalogued beside effect. Valkey needs Bun (`Bun.RedisClient`); the Postgres half runs under Node too.
