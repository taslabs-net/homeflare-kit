---
'@homeflare/config': minor
---

The shared git hooks fail closed: a hook that cannot run now stops the commit or push and names the fix, instead of skipping and exiting 0. A gate that cannot run is fixed, never skipped. This is `minor` because several things that used to pass now fail, and a consumer will see them on the first commit or push after upgrading.

- **A stale `.husky/` wrapper stops the hook.** The version bumper refreshes the dependency and never `.husky/*`, so every adopted repo still has the old wrapper, which exited 0 with no `node_modules`. On every `pre-commit` and `pre-push` the runner now compares `.husky/<hook>` with the current wrapper and fails with `bun node_modules/@homeflare/config/bin/hooks.ts install`; run it and commit `.husky/pre-commit` and `.husky/pre-push`. Only a file that starts with `# HomeFlare shared git hook` is compared, so a hook file a repo wrote for itself is left alone.
- **The `.husky/` wrapper exits 1 when `node_modules` is missing** (it exited 0), and when `bun` is not on `PATH` (it died with `exec: bun: not found`). A fresh worktree that has not run `bun install` can no longer commit or push unchecked; it prints one line, `run 'bun install' in this worktree`. The wrapper's bytes changed again, so `problemsInHooks` reports a committed copy as drift until you regenerate it.
- **`pre-commit` and `pre-push` fail without `node_modules`** instead of printing a note and returning. `pre-commit` still runs the secret scan first, which already failed closed when gitleaks is missing.
- **`pre-push` scans the pushed commits for secrets, first.** `gitleaks git --log-opts="<shas> --not --remotes=<remote>"` covers every commit the push adds, including cherry-picks, merges, rebases and `am`, for which git runs no `pre-commit`. A finding fails with "remove it, then ROTATE it", and a missing `gitleaks` now fails a push too.
- **`pre-push` fails when the working tree is not the commit.** Any change `git status --porcelain` shows, untracked files included and ignored ones not, fails the push with `commit or git stash -u, then push`. The lanes run on the working tree, so a green run on uncommitted edits certified nothing.
- **`pre-push` fails when a pushed ref is not the checked-out commit**, as in `git push origin other-branch` from a different branch. It used to print `NOT CHECKED` and exit 0, which let the unchecked ref through. The failure names the fix: check the ref out and push from there. An annotated tag at `HEAD` counts as checked out, because git reports the tag object's sha and the commit is what the hook compares.
- **One such ref fails the whole push, even alongside the checked-out one.** A push of `main` and `other-branch` from `main` used to measure `main` and only note the other. It now fails and names each ref to push on its own, the checked-out one first: `push main on its own, then check out other-branch and push from there`. Two refs at the same commit, such as `HEAD:a HEAD:b`, are both checked and pass.
- **`pre-push` fails when the repo has no `check` script** (it printed "nothing to run" and exited 0), and when every lane of `check` is skipped (it printed "0 lane(s) passed"). Put a lint, type or test lane in `check`; only `build` and `smoke` lanes are skipped, because CI runs them.
- **No failure message suggests a bypass.** The `bypass: git commit --no-verify` line is gone from every failure, and so is every comment arguing for it; a failure says what failed and the fix.

A package that lives in a subdirectory of its repository is not supported: the hooks look for `node_modules` at the repository root.
