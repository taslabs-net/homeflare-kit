Add `runRounds` and `mcpToolkit` to `@homeflare/seat-runtime`. `runRounds({ chat, toolkit, maxRounds, onRound })` is the one round loop the seats share: model turn, tool results, model turn, until the model asks for no tools or `maxRounds` tool rounds have run, and then ONE more turn with no toolkit and `toolChoice: 'none'` so a run ends in an answer (`capped` says the cap fired). `maxRounds` must be a positive integer or the run dies with a `RangeError` before any model call. Every turn is a `seat.round` span, counted in `seat_rounds_total` and `seat_rounds_capped_total`. `mcpToolkit(url, headers)` connects the official `@modelcontextprotocol/sdk` client (exact `1.31.0`, a new pinned dependency) over Streamable HTTP and returns the server's tools as a ready-to-run Effect AI toolkit (each a `Tool.dynamic` carrying the server's own JSON Schema) plus `listResources` and `readResource`. A tool failure (`isError`, a JSON-RPC error, a dropped call) is returned to the model as the tool's result; connecting and listing fail with `McpToolkitError`, whose message never holds a header or a query string. Results are text: image, audio and blob blocks become one-line markers. `@effect/ai-openai-compat` rc.115 cannot decode a tool call for a `Tool.dynamic` alone (fixed in rc.118), so an argument the server's schema does not declare is dropped until the pin moves.
